===============================================================================
1. RINGKASAN PROYEK
===============================================================================

Nama Aplikasi: Kota Pintar (Smart City)
Tujuan: Platform pelaporan masalah publik yang memungkinkan warga melaporkan 
        masalah infrastruktur kota (lubang jalan, banjir, sampah, dll) dan 
        secara otomatis mengarahkannya ke dinas pemerintah yang tepat menggunakan 
        AI.

Fitur Utama:
- Pelaporan masalah oleh warga dengan foto, lokasi GPS, dan deskripsi
- Klasifikasi otomatis menggunakan AI (Gemini)
- Routing cerdas ke departemen yang sesuai
- Pelacakan status laporan secara real-time
- Dashboard untuk Warga, Petugas, dan Admin
- Notifikasi real-time via WebSocket
- Sistem voting dan komentar
- Analytics dan KPI untuk admin
- Peta interaktif dengan visualisasi laporan

Target Pengguna:
1. Warga (Citizen) - Melaporkan dan memantau masalah
2. Petugas (Officer) - Menangani dan menyelesaikan laporan
3. Admin - Mengelola dinas, petugas, dan melihat analytics

3. ALUR KERJA APLIKASI (WORKFLOW)
===============================================================================

┌──────────────────────────────────────────────────────────────────────────┐
│              ALUR 1: PELAPORAN MASALAH OLEH WARGA                        │
└──────────────────────────────────────────────────────────────────────────┘

1. LOGIN/REGISTER
   └─> Warga membuat akun atau login ke sistem
   └─> Frontend: /register atau /login
   └─> Backend: POST /api/auth/register atau /api/auth/login
   └─> Response: JWT token disimpan di localStorage

2. BUAT LAPORAN
   └─> Warga ke halaman "Kirim Laporan" (/submit-report)
   └─> Input:
       • Judul masalah
       • Deskripsi detail
       • Foto (opsional)
       • Lokasi (GPS auto-detect atau manual pin di peta)
       • Alamat
   └─> Frontend: POST /api/reports/create
   └─> Data dikirim ke backend termasuk base64 foto

3. KLASIFIKASI AI (Backend)
   └─> Backend menerima laporan
   └─> Panggil ai_service.classify_report():
       • Input: title, description, image_base64
       • AI (Gemini) menganalisis dan return:
         - category: "Kerusakan Jalan", "Banjir", dll
         - urgency: "Kritis", "Tinggi", "Sedang", "Rendah"
         - sentiment: "Darurat", "Keluhan", "Saran", "Informasi"
         - confidence: 0-100
         - summary: ringkasan 1 kalimat
   └─> Jika AI gagal, gunakan fallback rule-based

4. ROUTING OTOMATIS
   └─> Berdasarkan category, tentukan department:
       • "Kerusakan Jalan" → Dinas Pekerjaan Umum
       • "Banjir" → Dinas Penanggulangan Bencana
       • "Sampah" → Dinas Kebersihan
       • dst...
   └─> Hitung SLA deadline berdasarkan kategori
   └─> Hitung priority_score berdasarkan urgency

5. SIMPAN KE DATABASE
   └─> Insert report ke MongoDB collection 'reports'
   └─> Status awal: "AI Classified"
   └─> Kirim notifikasi ke:
       • Admin: "Laporan baru diterima"
       • Petugas di department terkait

6. REAL-TIME UPDATE
   └─> WebSocket broadcast notifikasi
   └─> Dashboard warga update otomatis

7. KONFIRMASI
   └─> Warga dapat melihat laporan di dashboard mereka
   └─> Status, kategori, dan estimasi penyelesaian ditampilkan


┌──────────────────────────────────────────────────────────────────────────┐
│             ALUR 2: PENANGANAN LAPORAN OLEH PETUGAS                      │
└──────────────────────────────────────────────────────────────────────────┘

1. PETUGAS LOGIN
   └─> Login dengan akun officer
   └─> Redirect ke /officer-dashboard

2. LIHAT LAPORAN
   └─> Petugas melihat laporan yang assigned ke department mereka
   └─> Filter berdasarkan:
       • Status
       • Urgency
       • Category
   └─> Sort berdasarkan priority_score (tertinggi dulu)

3. AMBIL LAPORAN (ASSIGN)
   └─> Admin atau petugas senior assign laporan ke officer tertentu
   └─> PUT /api/reports/{id}/assign
   └─> Status berubah: "AI Classified" → "Assigned"
   └─> Notifikasi ke officer yang di-assign

4. MULAI BEKERJA
   └─> Officer update status: "Assigned" → "In Progress"
   └─> PUT /api/reports/{id}/status
   └─> Notifikasi ke warga: "Laporan sedang ditangani"

5. TAMBAH KOMENTAR
   └─> Officer bisa menambah update/komentar
   └─> POST /api/reports/{id}/comments
   └─> Warga bisa melihat progress

6. REVIEW
   └─> Setelah pekerjaan selesai:
   └─> Status: "In Progress" → "Under Review"
   └─> Admin atau supervisor review

7. SELESAI
   └─> Status: "Under Review" → "Resolved"
   └─> Timestamp resolved_at dicatat
   └─> Notifikasi ke warga: "Masalah telah diselesaikan"

8. TUTUP LAPORAN
   └─> Setelah konfirmasi, status: "Resolved" → "Closed"


┌──────────────────────────────────────────────────────────────────────────┐
│             ALUR 3: MANAJEMEN SISTEM OLEH ADMIN                          │
└──────────────────────────────────────────────────────────────────────────┘

1. ADMIN LOGIN
   └─> Login dengan role: admin
   └─> Redirect ke /admin/analytics

2. DASHBOARD ANALYTICS
   └─> GET /api/kpi
   └─> Lihat statistik:
       • Total reports
       • By status (pie chart)
       • By category (bar chart)
       • By department
       • Average resolution time
       • SLA compliance rate
       • Trend over time

3. MANAJEMEN DINAS
   └─> Halaman: /admin/departments
   └─> CRUD departments:
       • Buat dinas baru
       • Edit dinas
       • Assign categories ke dinas
   └─> Endpoints:
       • POST /api/departments/create
       • GET /api/departments/all
       • PUT /api/departments/{id}

4. MANAJEMEN PETUGAS
   └─> Halaman: /admin/officers
   └─> CRUD officers:
       • Tambah officer baru
       • Assign ke department
       • Edit profil officer
   └─> Endpoints:
       • GET /api/officers/all
       • POST /api/officers/create
       • PUT /api/officers/{id}

5. ROUTING RULES
   └─> Halaman: /admin/routing
   └─> Atur aturan routing:
       • Category → Department mapping
       • SLA hours per category
   └─> Endpoints:
       • GET /api/routing/rules
       • POST /api/routing/rules
       • PUT /api/routing/rules/{id}

6. MONITORING
   └─> Monitor semua laporan real-time
   └─> Reassign jika diperlukan
   └─> Intervensi jika SLA terlewat


┌──────────────────────────────────────────────────────────────────────────┐
│                  ALUR 4: FITUR INTERAKTIF                                │
└──────────────────────────────────────────────────────────────────────────┘

UPVOTING:
└─> Warga lain bisa upvote laporan yang sama
└─> POST /api/reports/{id}/upvote
└─> Priority_score meningkat dengan upvote
└─> Laporan populer mendapat perhatian lebih cepat

KOMENTAR:
└─> Warga, petugas, admin bisa berkomentar
└─> POST /api/reports/{id}/comments
└─> Thread diskusi untuk setiap laporan

PETA INTERAKTIF:
└─> Halaman /city-map
└─> Tampilkan semua laporan di peta (Leaflet)
└─> Marker berwarna berdasarkan urgency:
    • Merah: Kritis
    • Oranye: Tinggi
    • Kuning: Sedang
    • Hijau: Rendah
└─> Klik marker untuk lihat detail

NOTIFIKASI REAL-TIME:
└─> WebSocket connection: /ws/{user_id}
└─> Notifikasi otomatis untuk:
    • Laporan baru (admin/officer)
    • Status update (citizen)
    • Assignment (officer)
    • Komentar baru
    • Upvote milestone
└─> Badge count di navbar

6. FITUR-FITUR UTAMA
===============================================================================

A. AUTHENTICATION & AUTHORIZATION
   ├─ Register dengan email, nama, password
   ├─ Login dengan JWT token
   ├─ Role-Based Access Control (RBAC):
   │  ├─ Citizen: Buat laporan, lihat laporan sendiri, upvote, comment
   │  ├─ Officer: Lihat & tangani laporan, update status, comment
   │  └─ Admin: Full access, manajemen sistem, analytics
   └─ Protected routes dengan ProtectedRoute component

B. PELAPORAN MASALAH
   ├─ Form lengkap: title, description, photo, location, address
   ├─ Auto-detect GPS location
   ├─ Manual pin location di peta
   ├─ Upload foto (multiple)
   ├─ Preview sebelum submit
   └─ AI auto-classification

C. AI CLASSIFICATION
   ├─ Powered by Google Gemini (gemini-3-flash-preview)
   ├─ Analisis text + image
   ├─ Output:
   │  ├─ Category (11 kategori)
   │  ├─ Urgency (4 level)
   │  ├─ Sentiment (4 tipe)
   │  ├─ Confidence score (0-100)
   │  └─ Summary (ringkasan 1 kalimat)
   ├─ Fallback ke rule-based jika AI gagal
   └─ Validasi output untuk keamanan

D. SMART ROUTING
   ├─ Category → Department mapping
   ├─ SLA hours per category:
   │  ├─ Kriminalitas: 1 jam
   │  ├─ Banjir: 2 jam
   │  ├─ Kebocoran Air: 6 jam
   │  ├─ Lalu Lintas: 12 jam
   │  ├─ Sampah/Penerangan: 24 jam
   │  ├─ Kerusakan Jalan: 48 jam
   │  └─ Lainnya: 72 jam
   ├─ Priority score calculation:
   │  └─ Berdasarkan urgency + upvotes + nearby reports + confidence
   └─ Auto-assign ke department

E. DASHBOARD WARGA
   ├─ Lihat semua laporan yang dibuat
   ├─ Filter berdasarkan status
   ├─ Track progress laporan
   ├─ Klik untuk lihat detail
   ├─ Real-time status updates
   └─ Notifikasi center

F. DASHBOARD PETUGAS
   ├─ Lihat laporan di department mereka
   ├─ Filter & sort:
   │  ├─ By status
   │  ├─ By urgency
   │  ├─ By priority score
   │  └─ By category
   ├─ Ambil/assign laporan
   ├─ Update status
   ├─ Tambah komentar
   └─ Real-time updates

G. DASHBOARD ADMIN
   ├─ Analytics & KPI:
   │  ├─ Total reports

9. STATUS LAPORAN (LIFECYCLE)
===============================================================================

  1. Submitted          →  Laporan baru diterima sistem
  2. AI Classified      →  AI selesai klasifikasi, siap di-assign
  3. Assigned           →  Ditugaskan ke officer tertentu
  4. In Progress        →  Officer sedang mengerjakan
  5. Under Review       →  Pekerjaan selesai, menunggu review
  6. Resolved           →  Masalah telah diselesaikan
  7. Closed             →  Laporan ditutup (final state)

16. TROUBLESHOOTING
===============================================================================

Issue: Backend tidak start
Solution:
- Check logs: tail -f /var/log/supervisor/backend.err.log
- Verify MONGO_URL
- Pastikan semua dependencies terinstall
- Check port 8001 tidak digunakan

Issue: Frontend tidak connect ke backend
Solution:
- Verify REACT_APP_BACKEND_URL di .env
- Pastikan backend running
- Check CORS settings di backend
- Inspect network tab di browser

Issue: AI classification gagal
Solution:
- Check EMERGENT_LLM_KEY atau GEMINI_API_KEY
- Verify API key valid
- Check logs untuk error message
- Fallback akan otomatis ke rule-based

Issue: WebSocket disconnect
Solution:
- Check network connection
- Verify WebSocket URL
- Check browser console untuk errors
- Auto-reconnect seharusnya handle ini

Issue: File upload gagal
Solution:
- Check STORAGE_PATH exists dan writable
- Verify file size limits
- Check disk space
- Inspect backend logs
